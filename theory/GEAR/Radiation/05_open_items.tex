  \item[$\square$] \textbf{T9} -- \code{space\_regrid}'s top-level
    cell grid never re-refines once coarsened, even after the
    \code{h\_hii} that coarsened it shrinks back down (e.g.\ a star
    dies). Traced in code (2026-07-20), not yet fixed.
    \textbf{Per-star and per-cell bookkeeping is already correct}:
    \code{feedback\_common.c:372-378} explicitly resets
    \code{sp->h\_hii = 0.0} when a star dies or ages out of HII
    eligibility (comment: ``This prevents dead particles with large
    h\_hii to force the tasks at higher levels than necessary'',
    final value preserved in
    \code{sp->tracers\_data.final\_HII\_radius}), and
    \code{c->stars.h\_hii\_max} (the per-cell aggregate
    \code{space\_regrid} reads, Section~\ref{sec:space-regrid-hhii}) is
    recomputed fresh from current \code{sparts[i].h\_hii} at every
    tree rebuild/drift (\code{cell.c}, \code{cell\_drift.c},
    \code{space\_split.c}) -- so it does shrink correctly once a
    star's \code{h\_hii} resets. \textbf{The gap is one level up}:
    \code{space\_regrid.c}'s own regrid trigger,
    \begin{quote}
    \code{if (s->cells\_top == NULL || cdim[0] < s->cdim[0] || ...)}
    \end{quote}
    only fires when the newly-computed \code{cdim} is \emph{smaller}
    (coarser) than the grid's current \code{cdim} -- never when it
    would come out larger (finer) again. This is a general,
    pre-existing SWIFT property, true for ordinary hydro \code{h\_max}
    too, not introduced by this branch: once cells coarsen, they stay
    coarse for the rest of that run, regardless of why \code{h\_max}
    grew. \code{h\_hii} is the first mechanism in this codebase where a
    \emph{single, brief, transient} event (one star's HII region,
    possibly capped only by the periodic floor of 3,
    Section~\ref{sec:space-regrid-hhii}) can trigger this, unlike ordinary
    hydro resolution needs which are usually sustained, not transient.
    \textbf{Practical concern}: in a real multi-star simulation, one
    star's HII region growing large enough to coarsen \code{cdim} --
    even briefly, even down to the periodic floor -- would coarsen the
    whole box for the remainder of that run, even after that star dies
    and every other star stays small.

    \textbf{Decision (2026-07-21)}: scoped to h\_hii specifically, not a
    general change to the one-way coarsening ratchet ordinary
    hydro/star/black-hole/sink \code{h\_max} still relies on (ratchet
    behaviour for those is a pre-existing, general SWIFT property, out
    of scope for this branch). \code{space::h\_max\_no\_hii\_hwm}
    (\code{src/space.h}) is a new persistent high-water mark that
    reproduces the existing ratchet exactly for the non-\code{h\_hii}
    contributions to \code{h\_max}; \code{h\_hii}'s own contribution is
    recomputed fresh every regrid (no memory), and the regrid trigger in
    \code{space\_regrid.c} is now bidirectional (\code{cdim != s->cdim}
    instead of \code{cdim < s->cdim}). This is safe because \code{cdim}
    can only come out \emph{larger} (finer) than before when
    \code{h\_hii}'s contribution has shrunk -- the ratchet guarantees the
    ordinary-physics component never causes that direction on its own.
    Implemented in \code{src/space.h}/\code{src/space\_regrid.c}; builds
    clean (\code{swift}/\code{swift\_mpi}) under
    \code{-Werror -Wall -Wextra -Wshadow}. \textbf{Committed
    (2026-07-21)}: \code{testRadiationRebuildCheck} and
    \code{test27cellsStars} both pass, and a full STARBENCH re-run
    ($T_i=10^4\,$K forced, the same edge case that pins
    \code{max\_top\_level\_cells: 3} at the periodic boundary) completed
    end to end at $9.23\%$ (vs.\ $6.12\%$ pre-change -- within the
    scatter expected from this example's probabilistic boundary
    ionization, not attributed to a regression).

    \textbf{Complementary general safety, also added}: a new
    \code{Scheduler:min\_top\_level\_cells} parameter (default 3,
    mirroring the existing \code{Scheduler:max\_top\_level\_cells}) sets
    \code{space::cell\_max\_width}, a ceiling on the effective cell width
    that \code{space\_regrid()} will not coarsen past regardless of what
    is driving the coarsening (ordinary \code{h\_max} or \code{h\_hii}).
    This bounds the worst case even if the bidirectional trigger above
    never actually gets exercised in a given run.

    \textbf{Explicitly unverified}: whether the bidirectional trigger is
    reachable in practice for a continuously star-forming cosmological
    box (as opposed to quiescent periods, isolated-galaxy/zoom tests, or
    bursty SF) is an untested hypothesis, not a measured result -- no run
    has yet checked whether \code{cdim} actually gets a chance to shrink
    back in a continuous-SF setting. The STARBENCH re-run that
    accompanied the 2026-07-21 commit above did not exercise this either:
    STARBENCH's single star never dies within the run's $\sim$3\,Myr
    duration (far short of its lifetime), so \code{h\_hii} never shrinks
    back down and the re-refine path was likely never triggered -- that
    run only confirmed no regression, not that the fix's core mechanism
    works.

    \textbf{TODO (added 2026-07-23, from a direct question about whether
    this had ever actually been checked): explicitly verify the
    coarsen-then-re-refine cycle}, in two places:
    \begin{itemize}
      \item \code{HomogeneousBox} (T4's planned isolated-galaxy/
        continuous-SF test) -- as originally planned above.
      \item \textbf{StromgrenSphere} -- a single star whose \code{h\_hii}
        grows then shrinks back to zero (e.g.\ by running well past that
        star's lifetime, or reusing \code{HII\_max\_age\_Myr} to force
        early HII shutoff) is a much cheaper, more controlled way to
        directly exercise both directions of the trigger than a full
        continuous-SF box -- worth doing \emph{first}, before the
        more expensive \code{HomogeneousBox} test.
    \end{itemize}
    In both cases, check \code{cdim}/top-level cell count directly
    (e.g.\ via logged regrid messages or \code{task\_level}/dependency-graph
    output showing the grid actually refining back to more cells) rather
    than only checking the final physics result, since a physics-level
    check alone would not distinguish ``re-refined correctly'' from
    ``never needed to re-refine.''

    \textbf{Deferred refinement (decision 2026-07-27)}: once the
    bidirectional trigger is verified, consider hysteresis on the
    \emph{refine} direction only (require the finer \code{cdim} to
    persist for a dwell time before rebuilding, so a flickering
    \code{h\_hii} near a \code{cdim} boundary cannot thrash the
    top-level grid); coarsening stays immediate. Not implementable
    responsibly until the verification runs above exist to test it
    against.

  \item[$\square$] \textbf{T11} -- Quadrature bias for declining
    emission rates. The photon budget integrates
    $\dot N_{\rm ion}(t_{\rm now}) \times \Delta t_{\rm back}$ -- a
    backward rectangle rule evaluated at the \emph{end} of the elapsed
    interval. For an individual star this is exact (the fit is
    age-independent until death), but for an SSP population particle
    whose $\dot N_{\rm ion}(t)$ declines over the interval it
    systematically \emph{under}-issues photons: the end-of-interval
    rate is below the interval average. Bounded by one rebuild interval
    of decline (small at the $0.1\,$Myr production cadence against
    $\sim$Myr SSP decline timescales), zero for growing rates in this
    convention only if they are re-evaluated -- the clean fix is a
    trapezoid rule, which needs one cached previous-pass rate per star
    in \code{feedback\_spart\_data} (restart-visible, so bump the
    restart-compatibility check when adding it). Deferred; revisit
    together with the pychem table work (T7), which touches the same
    emission-rate evaluation.
